# Comece aqui — AppSec

## Para quem

Pessoas que precisam conectar requisitos de segurança, revisão de desenho, testes de autorização e regressões ao ciclo de desenvolvimento de aplicações web e APIs.

## Rota guiada

### 1. Definir

**Atividade:** Descrever abuso e requisito verificável.

**Saída:** Critério de segurança.

### 2. Verificar

**Atividade:** Testar acesso permitido e negado.

**Saída:** Matriz de autorização.

### 3. Sustentar

**Atividade:** Manter regressões na evolução do produto.

**Saída:** Evidência de revisão.


## Sessão inicial

Abra [O objeto de outro cliente](../examples/caso-01.md), leia as evidências e faça uma primeira análise antes de abrir o comentário. Copie a [ficha de trabalho](../templates/ficha.md) para seu caderno e preencha os campos. Compare sua conclusão com o critério de aceite.

**Critério de conclusão:** A matriz demonstra autorização no servidor por objeto e contexto, sem depender apenas de esconder botões.

## Fronteira editorial

Este projeto aplica requisitos ao produto. Threat-Modeling é biblioteca de manuais; VulnerabilityResearch investiga causas de falhas; Cloud trata infraestrutura.
